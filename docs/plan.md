# 开发计划表

依据：`docs/design/rag-platform-design.html` 第 19 章的 P0 到 P8。每一行是一个子需求，对应 `specs/` 下的一份 spec，由一个干净上下文的子 agent 开发、另一个子 agent 评审（流程见 `CLAUDE.md`）。

**排序规则**：先按阶段（P0 到 P8）排；同一阶段里，被别人依赖的排前面；同样没有依赖时，不调模型的排前面（预算用完、网关出问题时也能继续做）。

**状态**：待做、进行中、评审中、完成、暂停（原因写在 `docs/progress.md`）。

## 预算和模型

- 这一轮通宵开发的模型花费上限是 30 元，账本在 `data/cost/ledger.jsonl`。
- 预算不够或网关调不通时，先用假模型把代码和测试做完，标「暂停：等真实模型」，先做不调模型的子需求。
