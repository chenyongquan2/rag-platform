# P4 报告：MT5 手册摄取和检索实验

这份报告随 P4 的子需求逐节增加。现在只有 P4-01（摄取）一节；P4-02（题集和分析器对比）做完以后加第二节。

## 1. P4-01 MT5 手册摄取

日期：2026-10-20，分支 `spec/P4-01-mt5-ingest`。原始记录在 git 忽略的 `data/reports/mt5/`（质量报告、摄取报告、估算）。这一节没有手册里的任何文字：只有数字、页面数和我自己写的说明。

### 1.1 这一节回答什么

1. 两个 CHM 文件长什么样：能不能读出来，编码和目录有没有坑，中文版和英文版的页面怎么对上。
2. 页面里有哪些噪声，清掉了多少，有没有清掉正文。
3. 两个语言版本怎么放进索引，搜索时怎么避免同一页出现两次。
4. 写进索引花了多少钱。
5. 只用页面标题写的问题，能不能把对应的页面找回来（冒烟检索，不是评测）。

### 1.2 先说几个词

| 词 | 意思 |
|---|---|
| CHM | Windows 的帮助文件格式，一个文件里装着很多 HTML 页面、一份目录和一份索引。手册有两个：中文版、英文版。 |
| 解包 | 把 `.chm` 文件解成一个普通文件夹（页面、图片、目录文件）。用 7-Zip 做。 |
| 目录文件 `.hhc` | 手册左边那棵目录树。里面有每个页面的名字和它在树里的位置，用来给每个页面写「标题路径」。 |
| 索引文件 `.hhk` | 关键词到页面的对照表。这次读了它，但没有写进索引。 |
| 标题路径 | 从目录树最上面一层到这个页面的名字，例如「工具 > 某个类 > 某个方法」，用 `>` 连起来。每个块的向量文字里都带着它。 |
| page_key | 页面在 CHM 里的路径去掉扩展名、转小写，例如 `widget_add`。同一页的中文版和英文版的 page_key 相同，用它把两个版本认成同一页。 |
| 块 | 一个页面按标题和长度切成的小段，是写进索引、被检索的单位。 |
| 清洗规则 | 一条有名字、能开关、有正反例测试的处理，处理对象是读出来的页面文字。 |
| 删除量保护 | 清洗规则一次删掉太多字符时，摄取直接停下来、什么都不写。 |
| 冒烟检索 | 随便问几个问题，看正确的页面会不会出现在结果里。只能看出「有没有明显坏掉」，不能算准确率。 |

### 1.5 噪声和清洗规则

结论先说：这本手册很整齐，要清的东西少。设计 6.2 列的「另见」栏目、版权页脚、跳转页、重复标题，在这两本书里基本不存在，所以没有写这些规则。量到的有：

| 噪声 | 在哪一步去掉 | 页数 | 去掉的量 |
|---|---|---|---|
| 页首导航条（面包屑、上一页和下一页的图片） | 读取页面时（它在正文容器外面） | 12,599 | 690,490 个可见字符 |
| 只有 `&nbsp;` 的空段落 | 读取页面时 | 8,837 | 8,905 个段落 |
| 没有文字的锚点 `<a name>` | 读取页面时 | 309 | 1,076 个 |
| 页面标题和目录里的页面名相同（标题回声），规则 `chm_title_echo` | 清洗 | 1,283（约 10%） | 18,648 个字符，占全部输入的 0.2% |
| 文字完全相同的页面（`dedupe`） | 清洗 | 0（见下） | 0 |
| 一行列表项里多出的 `>`（原文笔误） | 没有写规则 | 2（每个语言 1 页） | 0 |
| 空页面、太短的页面、只有目录的页面 | 清洗（`skip_empty`） | 0 | 0 |
| 多余的空白、空行（`whitespace`） | 清洗 | 0 | 0 |

- 文字完全相同的页面有 35 页（中文 19、英文 16），它们在目录里的位置不同（例如 Admin API 下一页和 Manager API 下一页的同一份说明）。第一版按「语言」去重，每组只留一页，审查指出这会让问 Manager API 的问题只能找到 Admin API 的页面。现在按「语言加标题路径」去重，标题路径不同的都留，所以最终一页没丢（见 `docs/decisions.md`）。
- 每条会删字符的读取规则和清洗规则都有一个正例和一个反例测试：例如导航规则的反例是「正文里的表格表头写着 Previous、Next」，必须留下；标题回声的反例是「标题比目录名长」「第二个同名标题」，必须留下。整条链还有一个反例测试：正文里写着 `a < 0`、`Vec<T>`、`<b>` 字样的页面，读完、清洗完、切块完，这些字都在。
- 删除量保护：`kb/private/mt5.yaml` 里每条会删字符的清洗规则都配了上限（页面 30% 到 50%，全体 2% 到 5%）。真实运行没有触发。测试里造了触发的情况：单页超限、全体超限、整页被丢掉的算进全体，错误信息只写规则名、页面 id 和比例。

### 1.6 保真度：有没有文字在转换时丢了

审查第 1 轮发现：读取器转换「注意框」时只取里面的段落，框里的列表等内容丢了，8 页（中英文各 4 页）少了一小段正文。已修，并加了检查：每页把页面可见文字里的字母、数字、汉字，和转出来的 Markdown 里的做多重集合比较（先去掉转换自己加的图片标记和链接网址），少的字符数记进读取统计和质量报告（`fidelity: lost X of Y`），有损失的页面列出页面 id。

真实结果（12,599 页）：可见的字母、数字、汉字共 8,305,764 个，丢失 0 个，有损失的页面 0 页。修之前审查查到 8 页。导航条、空段落、空锚点不含文字，不算损失；清洗阶段（标题回声）删的字符另有统计。

### 1.8 中英文分组

- 每个块在索引里带 `language`（`zh` 或 `en`，由页面来自哪本书决定，不靠猜）、`page_key`、`links_to`、`title_path`。可以按语言过滤。
- 搜索结果里同一页的两个版本只留一个：`retrieval.dedupe_by_page_key: true`（`mt5` 打开，`hf_docs` 关闭）。留哪个：问题里有两个以上汉字就留中文版，否则按问题的语言检测；问题的语言不在里面就留排名靠前的块的语言。只有一个版本的页面不受影响。同一页的另一个语言版本也匹配了这次搜索时，留下的块带 `also_matched_languages`（只反映本次候选，不说明页面有哪些语言）。做法和理由见 `docs/decisions.md`。
- 配对情况：6,273 页两个语言都有，53 页只有英文版，0 页只有中文版。

### 1.10 冒烟检索

做法：写 15 个问题，只看页面的标题（目录里的名字和路径）来写，不看正文：英文 10 个、中文 5 个。用真实的检索链（混合检索、重排、阈值 0.3、同一页只留一个语言版本），每题取前 10 个块，看目标页面（按 page_key）排第几。这只是冒烟：题少，题是我自己写的，选的页面也是我挑的，不能当作准确率；真正的题集是 P4-02。题目和结果没有提交（题目由页面标题改写而来）。下面是最终索引（整本都写完以后）的结果；中文题在中文只写了一部分时（第一轮）也量过一次，结果是 12、13、14（排第 1、前 3、前 10）。

| 结果（15 题） | 数量 |
|---|---|
| 目标页面排第 1 | 11 |
| 目标页面排前 3 | 13 |
| 目标页面在前 10 | 14 |
| 没找到（返回「没有相关内容」） | 1（一个问「添加某类记录时触发什么事件」的英文题，所有块的重排分都低于 0.3） |

- 中文题的结果现在都只含中文版页面（5 题，同一页只留中文版）；其中 2 题目标页面排第 2（第一轮是排第 1 和第 2，差别在于完整索引里多了中文页面）。英文题里 1 题目标页面排第 5。
- 英文题里有一题（问「网关关闭时调用什么」）目标页面排第 1，但留下的是中文版：这一页的英文块没有进入候选，只有中文块进了，按规则「只有一个版本时保留」，所以结果里是中文版。这说明「问题语言的版本」不一定在候选里。
- 第一次冒烟时网络不稳，几个问题的向量没取到（只用了关键词那一路），重排也超时了；这些结果作废，上面的数字是把检索截止时间调到 60 秒、查询向量超时调到 20 秒重跑的，没有降级提示。

### 1.11 没做的、没验证的、限制

- 没有真实的中文文件名可测；没有一页的编码声明是真的说谎，这种情况只在合成的测试页里验证过。
- 手册里的图片（463 个标记）只留了标记和文件路径，图片本身不处理（P6）。表格被块大小切断时不重复表头（488 处），表格处理是 P2 的事。
- 索引里 `links_to`（页内链接指向的页面）写进了，但检索结果不返回它，也没有「顺着链接取页面」的功能。`.hhk` 关键词读了但没有写进索引。
- `get_context` 取「另一个语言版本」这一步没做；`also_matched_languages` 只说明本次搜索里另一个版本也匹配了。
- 分析器是 `standard`（中文按单字切）；cjk、IK、smartcn、icu 的对比是 P4-02。
- 变异检查：在仓库的一个副本里每次改一处代码、只跑相关测试，共约 60 处。第一轮有 4 处没被测试抓住（质量报告里跳过的页面没有按语言分开统计；解包记录里带了本机路径但测试没发现；读取器不用连接器给的 page_key 也没人发现；规则的 `units_seen` 没人检查），补测试后都抓住了。审查第 1 轮又指出两处测试缺口（解码顺序里把 UTF-8 放最后、去掉「控制字符或替换字符」的检查，测试都不失败），补测试后抓住；还剩 1 处等价改动（解包后的文件名过滤「`#`、`$` 开头的文件」，这类文件本来就不是 `.htm`）。
- 写测试的先后：读取和 CHM 数据来源的测试先写、先运行（模块不存在，全部报错），再写代码；清洗规则、质量报告、检索分组和配置的测试是和代码同一轮写的，没有单独留一次「先红」的运行记录。审查第 1 轮的修复（注意框、保真度）的测试先写，先运行得到失败（缺函数、缺字段、缺内容），再写代码。
- 这条分支的提交历史在审查后重写过（把早期提交里的真实页面名和一句真实正文清掉），最终文件内容和测试过的一致。
